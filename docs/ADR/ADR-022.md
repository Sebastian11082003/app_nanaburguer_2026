# ADR-022: Costeo de inventario por última compra

| Campo | Detalle |
|-------|---------|
| Estado | ACCEPTED |
| Fecha | 2026-08-12 |
| Versión producto | v0.5.1 |
| Decisión | `InventoryItem.costCentsPerUnit` = costo de la última `PURCHASE_IN` |

---

## Contexto

Para margen de plato y valuación operativa hace falta un costo unitario
por insumo. Alternativas típicas:

1. **Última compra** — simple, refleja precio reciente
2. **Promedio móvil** — más estable, más lógica y estados
3. **FIFO / capas** — correcto contable, complejidad alta

Fase 2 prioriza margen operativo usable, no libro mayor completo.

## Decisión

1. Al registrar `PURCHASE_IN` con `unitCostCents`, se actualiza
   `InventoryItem.costCentsPerUnit`.
2. Costo de receta = Σ (`quantityPerServing` × `costCentsPerUnit`).
3. Al cerrar orden: `SALE_CONSUME` descuenta stock según BOM; si no hay
   stock suficiente, se rechaza el cierre (misma transacción).
4. Proveedores / OC formales quedan para fase Compras.

## Alternativas rechazadas (por ahora)

- Promedio móvil ponderado — se puede añadir sin romper API si se
  documenta en un ADR posterior.
- FIFO — fuera de alcance hasta exportación contable.

## Consecuencias

- Margen en UI de recetas puede cambiar tras cada compra.
- Ajustes / mermas no cambian costo unitario.
- Docs: `docs/functional/inventory-costs-spec.md`, `docs/ops/inventory.md`.
