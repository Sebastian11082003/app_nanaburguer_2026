# ADR-024: Clase de producto — POS SaaS (no ERP)

| Campo | Detalle |
|-------|---------|
| Estado | ACCEPTED |
| Fecha | 2026-09-20 |
| Versión producto | v0.4.51 |
| Decisión | RestoOS es un POS SaaS multi-tenant para restaurantes y gastrobares. No es un ERP. |

---

## Contexto

DEC-008 (v0.4.20) clasificó el producto como “ERP vertical gastronómico” para distinguirlo de un POS de una sola tienda. Esa etiqueta enredó alcance, backlog y agentes: se empezó a tratar inventario, contabilidad y CxC como si el destino fuera un ERP.

La referencia comercial acordada con el product owner es **Loggro Restobar**. En el catálogo de Loggro, Restobar está bajo **POS para bares y restaurantes**, separado de:

- Software administrativo para Pymes
- ERP para grandes empresas

La infraestructura real es un monolito de tres contenedores (Next.js + NestJS + PostgreSQL). Eso opera un salón, no un suite ERP.

## Decisión

1. **Clase:** POS SaaS para restaurantes y gastrobares, multi-tenant.
2. **Marca de plataforma:** RestoOS. **Piloto:** Nana Burger (`nana-neiva`).
3. **Núcleo:** mesas, órdenes, KDS, caja, domicilio/llevar, roles, reportes operativos, backoffice de plataforma.
4. **No es:** ERP, contabilidad, nómina, plan de cuentas, software administrativo horizontal.
5. Inventario, menú digital o facturación electrónica, si se piden después, son **módulos de un Restobar**, no un cambio de categoría a ERP.

DEC-008 en `.ai-engineering/PROJECT_DECISIONS.md` queda reescrita. La entrada de changelog v0.4.20 se conserva como histórico; esta ADR la sustituye.

## Alternativas rechazadas

- **Seguir llamándolo ERP vertical:** el dueño del producto lo rechazó; Loggro usa ERP para otro producto.
- **POS de una sola tienda (sin plataforma):** contradice el login de plataforma, el slug y el aislamiento por `restaurantId`.
- **ERP “de a poco” vía backlog financiero:** convierte cada módulo en una redefinición silenciosa del sistema.

## Consecuencias

- Docs de producto (`PROJECT_*`, alcance funcional, sdd-mapping) usan POS SaaS, no ERP.
- El backlog no puede marcar una fase “ERP” como destino.
- Agentes no inventan módulos contables para “completar el ERP”.
- Trabajo actual: local (Docker), no VPS.
