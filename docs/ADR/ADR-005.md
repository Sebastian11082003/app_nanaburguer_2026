# ADR-005 — Authentication Strategy

| Campo                      | Detalle                    |
| -------------------------- | -------------------------- |
| **Estado**                 | ✅ Accepted                |
| **Fecha**                  | 2026-05-10                 |
| **Autor**                  | NanaBurger SaaS Team       |
| **Patrón / Principio**     | Stateless Authentication   |
| **Tecnologías**            | JWT, bcrypt, NestJS Guards |
| **Impacto arquitectónico** | Crítico                    |

---

# Contexto

NanaBurger SaaS requiere autenticación segura para:

- administradores,
- cajeros,
- meseros,
- operadores delivery.

El sistema maneja:

- pagos,
- pedidos,
- reportes,
- cierres de caja,
- operaciones críticas.

Se necesita:

- autenticación desacoplada,
- REST compatibility,
- cloud readiness,
- escalabilidad,
- seguridad.

---

# Problema

¿Cómo implementar autenticación:

- segura,
- escalable,
- desacoplada,
- preparada para cloud,
  sin depender de sesiones tradicionales?

---

# Opciones Consideradas

## Session-Based Authentication

### Beneficios

| ✅ Beneficios     |
| ----------------- |
| Tradicional       |
| Fácil implementar |

### Problemas

| ❌ Problemas           |
| ---------------------- |
| Escalabilidad limitada |
| Session storage        |
| Stateful architecture  |

---

## OAuth Authentication

### Beneficios

| ✅ Beneficios    |
| ---------------- |
| Login externo    |
| Third-party auth |

### Problemas

| ❌ Problemas        |
| ------------------- |
| Overengineering MVP |
| Dependencia externa |

---

## JWT Authentication

### Beneficios

| ✅ Beneficios        |
| -------------------- |
| Stateless            |
| REST-friendly        |
| Escalable            |
| Cloud-ready          |
| Frontend desacoplado |

### Problemas

| ❌ Problemas      |
| ----------------- |
| Token revocation  |
| Secret management |

---

# Decisión

Se implementará:

# JWT Authentication

usando:

- Access Tokens,
- bcrypt hashing,
- NestJS Guards,
- RBAC Authorization.

---

# Arquitectura de Autenticación

## Login Flow

```text
Client
→ Login Request
→ Auth Controller
→ Auth Service
→ JWT Generation
→ Access Token
→ Protected Endpoints
```

---

# JWT Payload

```json
{
  "sub": "user-id",
  "email": "admin@nanaburger.com",
  "role": "ADMIN"
}
```

---

# Password Strategy

| Estrategia      | Implementación        |
| --------------- | --------------------- |
| Hashing         | bcrypt                |
| Salt Rounds     | 10                    |
| Plain passwords | ❌ Nunca              |
| Secret storage  | Environment Variables |

---

# Security Flow

```text
Login
→ Validate Credentials
→ Generate JWT
→ Client stores token
→ Authorization Header
→ JWT Guard
→ Roles Guard
→ Protected Route
```

---

# Threat Analysis

| Riesgo              | Mitigación           |
| ------------------- | -------------------- |
| Token leakage       | HTTPS                |
| Weak passwords      | bcrypt               |
| Brute force         | Future rate limiting |
| Secret exposure     | .env                 |
| Unauthorized access | Guards + RBAC        |

---

# Beneficios

| ✅ Beneficios        | ⚠️ Trade-offs       |
| -------------------- | ------------------- |
| Escalable            | Revocación compleja |
| Stateless            | Manejo expiration   |
| Frontend desacoplado | Secret rotation     |
| Cloud-ready          | JWT invalidation    |

---

# Consecuencias

## Positivas

- autenticación desacoplada,
- arquitectura moderna,
- REST-friendly,
- cloud-ready,
- preparada para SaaS.

---

## Negativas

- expiración tokens,
- invalidación compleja,
- manejo seguro de secrets requerido.

---

# Riesgos

| Riesgo        | Mitigación             |
| ------------- | ---------------------- |
| JWT hijacking | HTTPS                  |
| Token replay  | Expiration             |
| Secret leak   | Environment management |

---

# Futuro

Permitirá:

- refresh tokens,
- MFA,
- OAuth providers,
- tenant-aware auth,
- secure cookies.
