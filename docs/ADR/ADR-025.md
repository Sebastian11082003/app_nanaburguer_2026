# ADR-025: Facturación electrónica como puerto + simulador local (HU-026)

| Campo | Detalle |
|-------|---------|
| Estado | ACCEPTED |
| Fecha | 2026-09-23 |
| Versión producto | v0.4.55 |
| Decisión | HU-026 se cubre con un puerto `BillingProvider` y un simulador local. Factus/DIAN real queda como adaptador futuro. |

---

## Contexto

HU-026 pide integrar facturación electrónica, generar documentos fiscales y
guardar la respuesta del proveedor. El MVP ya emitía un snapshot POS y un
“aceptar” que inventaba un CUFE sin persistir payload. Factus/DIAN real está
fuera del piloto (ADR-024, alcance funcional).

## Decisión

1. Puerto `BillingProvider` (`issue` / `reject`).
2. Adaptador actual: `SimulatedBillingProvider` (`SIM-…`, payload en
   `responseJson.electronicBilling`). El snapshot de impresión no se pisa:
   `GET /invoices/:id/print` lo recorta.
3. Solo se emite o rechaza en estado `PENDING`.
4. Un adaptador Factus posterior reusa el mismo puerto.

## Alternativas rechazadas

- Llamar Factus/DIAN en el piloto: no hay ambiente fiscal ni llaves reales.
- Sobrescribir `responseJson` con el payload fiscal: rompe el recibo POS.

## Consecuencias

- `POST /invoices/:id/accept` y `POST /invoices/:id/reject`.
- WhatsApp (HU-027) y pasarela (HU-028) no entran en este corte.
