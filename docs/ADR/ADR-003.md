# ADR-003 — ORM Selection

| Campo                         | Detalle     |
| ----------------------------- | ----------- |
| **Estado**                    | ✅ Accepted |
| **ORM seleccionado**          | Prisma ORM  |
| **Impacto arquitectónico**    | Alto        |
| **Base de datos relacionada** | PostgreSQL  |

---

# Contexto

El proyecto requería:

- ORM moderno,
- TypeScript-first,
- migrations,
- relaciones complejas,
- productividad alta.

---

# Problema

¿Cómo manejar persistencia de datos:

- mantenible,
- escalable,
- segura,
- tipada?

---

# Opciones Consideradas

## Raw SQL

### Beneficios

| ✅ Beneficios    |
| ---------------- |
| Máximo control   |
| Alto rendimiento |

### Problemas

| ❌ Problemas       |
| ------------------ |
| Mucho boilerplate  |
| Baja productividad |

---

## TypeORM

### Beneficios

| ✅ Beneficios      |
| ------------------ |
| Integración NestJS |
| Maduro             |

### Problemas

| ❌ Problemas         |
| -------------------- |
| Menor type safety    |
| Migrations complejas |

---

## Prisma ORM

### Beneficios

| ✅ Beneficios |
| ------------- |
| Type-safe     |
| Excelente DX  |
| Schema-driven |
| Moderno       |

### Problemas

| ❌ Problemas             |
| ------------------------ |
| Menos control low-level  |
| Prisma Client dependency |

---

# Decisión

Se adopta:

# Prisma ORM

como ORM principal.

---

# Beneficios

| ✅ Beneficios           | ⚠️ Trade-offs                   |
| ----------------------- | ------------------------------- |
| Type safety             | Menos control SQL               |
| Excelente productividad | Prisma dependency               |
| Migraciones limpias     | Query avanzada requiere raw SQL |

---

# Riesgos

| Riesgo         | Mitigación             |
| -------------- | ---------------------- |
| Schema drift   | Migrations controladas |
| Queries lentas | Indexing strategy      |

---

# Futuro

Permitirá:

- multi-tenant future,
- read replicas,
- AWS RDS,
- escalabilidad cloud.
