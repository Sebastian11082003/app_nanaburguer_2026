# ADR-004 — Database Selection

| Campo                      | Detalle     |
| -------------------------- | ----------- |
| **Estado**                 | ✅ Accepted |
| **Base de datos**          | PostgreSQL  |
| **Impacto arquitectónico** | Crítico     |

---

# Contexto

El sistema requiere:

- transacciones,
- integridad relacional,
- reportes,
- consistencia,
- escalabilidad.

---

# Problema

¿Qué motor de base de datos garantiza:

- consistencia,
- reporting,
- SaaS readiness,
- cloud deployment?

---

# Opciones Consideradas

## MySQL

### Beneficios

| ✅ Beneficios |
| ------------- |
| Maduro        |
| Popular       |

### Problemas

| ❌ Problemas       |
| ------------------ |
| Menor flexibilidad |
| Reporting limitado |

---

## MongoDB

### Beneficios

| ✅ Beneficios |
| ------------- |
| Flexible      |
| Schema-less   |

### Problemas

| ❌ Problemas          |
| --------------------- |
| Débil relacionalmente |
| Reporting complejo    |

---

## PostgreSQL

### Beneficios

| ✅ Beneficios       |
| ------------------- |
| ACID                |
| Excelente reporting |
| Escalable           |
| Cloud-ready         |

### Problemas

| ❌ Problemas             |
| ------------------------ |
| Mayor complejidad tuning |

---

# Decisión

Se adopta:

# PostgreSQL

como motor principal.

---

# Beneficios

| ✅ Beneficios         | ⚠️ Trade-offs         |
| --------------------- | --------------------- |
| Integridad relacional | Mayor complejidad     |
| Reporting avanzado    | Más tuning            |
| Escalable             | Requiere optimización |

---

# Riesgos

| Riesgo            | Mitigación |
| ----------------- | ---------- |
| Queries lentas    | Indexes    |
| Growth complexity | Monitoring |

---

# Futuro

Permitirá:

- AWS RDS,
- backups automáticos,
- read replicas,
- partitioning.
