# ADR-006 — Role-Based Access Control (RBAC)

| Campo                      | Detalle     |
| -------------------------- | ----------- |
| **Estado**                 | ✅ Accepted |
| **Patrón**                 | RBAC        |
| **Impacto arquitectónico** | Alto        |

---

# Contexto

El sistema posee múltiples roles:

- ADMIN
- CASHIER
- WAITER
- DELIVERY

Cada rol requiere permisos limitados.

---

# Problema

¿Cómo controlar acceso granular:

- seguro,
- mantenible,
- desacoplado?

---

# Decisión

Se implementará:

# RBAC usando Guards + Decorators

---

# Roles

| Rol      | Responsabilidad  |
| -------- | ---------------- |
| ADMIN    | Control total    |
| CASHIER  | Cobros y cierres |
| WAITER   | Pedidos y mesas  |
| DELIVERY | Domicilios       |

---

# Implementación

```ts
@Roles(UserRole.ADMIN)
@UseGuards(JwtAuthGuard, RolesGuard)
```

---

# Beneficios

| ✅ Beneficios       | ⚠️ Trade-offs     |
| ------------------- | ----------------- |
| Seguridad modular   | Más decorators    |
| Escalable           | Más testing       |
| Fácil mantenimiento | Mayor complejidad |

---

# Riesgos

| Riesgo            | Mitigación   |
| ----------------- | ------------ |
| Acceso indebido   | Guards       |
| Roles incorrectos | Testing RBAC |

---

# Futuro

- permisos dinámicos,
- multi-tenant RBAC,
- permisos por sucursal.
